# 验证停止合同

在增加第二层验证、测试辅助设施、故障注入，或为测试与验证工具再写测试前读取本合同。目标是以足够证据证明当前命题，然后停止。

## 最小直接证明

1. 先写清命题、owner、最低成本的直接 seam、oracle 和 non-proof boundary。
2. 一个命题默认只在该 seam 证明一次。新增验证层必须说明它覆盖的、上一层没有覆盖的具体风险。
3. 业务、安全或恢复不变量及其决定性反例已经被真实观察后停止；“证据还能更完整”本身不是继续建设的理由。

## 禁止 proof-of-proof

测试 helper、fixture、故障注入器和验证脚本不是独立产品。除非它进入生产、能够直接破坏生产数据，或已成为多个真实任务共同依赖且具有非平凡行为，否则不为它建立独立验证体系。

如果证明验证工具又要求新的 helper、fixture、故障平台或验证层，停止并简化原证明。

## 有限信任锚点

官方数据库、操作系统、容器平台和外部产品在其版本化正式合同内是 scoped trust anchor（有限信任锚点）。项目只验证自己的适配假设、项目差异、已知缺口与失败处理，不证明第三方内部全部不变量。

只有项目依赖未记录行为、已有缺陷或兼容性证据，或第三方合同边界本身就是当前命题时，才继续验证该边界。

## 停止并回报

出现以下任一情况时，不继续加测试或设施：

- 第二层验证说不出新的具体风险；
- 开始测试测试代码，或验证验证工具；
- 新增 fixture、故障注入、checksum、sidecar、cleanup 或 finalizer 只为提高证明形式完整度；
- 测试与 harness 改动显著超过生产改动，却不能逐项映射到不同的任务不变量；
- 审查要求已经越过当前命题、owner 或可达场景。

回报已有证明、尚未证明的真实风险和扩张原因，然后只选择：简化证明、把成立的独立问题转任务外跟踪，或在目标、风险或授权需要改变时请求裁决；跟踪与发布按宿主项目的规则及用户授权执行。不得以继续堆叠验证作为默认动作。
