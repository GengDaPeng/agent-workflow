# Git 协作约定

本文只写多代理协作中磨合出的共同约定，Git 与 `gh` 的常规用法不再赘述。开始前读取项目参数文件 [`docs/agents/git.md`](../../../docs/agents/git.md)，项目授权与分级以它指向的规则为准。参数文件应提供：

- 主线 ref 与 Git 写入包装器；
- 提交前、PR 预检、仅交付信息校验、Ready、合并前的命令；
- CI 请求方式与证据规则；
- 分级与初始 PR 状态、交付 Skill、合并方式；
- 冲突与裁决的责任方；
- 工具专属的检出规则。

参数文件缺失的项按本文默认值执行。引用本 Skill 的某一节时，只执行那一节。

## 工作区与写入

- 一个任务对应一个 worktree 和一条任务分支。主工作区只停在主线；工具 Handoff 带来的临时检出按参数文件处理。
- 建分支：`git fetch <remote> && git worktree add --no-track -b <type>/<任务编号>-<topic> <路径> <主线ref>`。子任务以父任务的精确 SHA 为基点，在自己的新 worktree 里建，不在父工作位切分支。分支前缀约定为 `feature`、`fix`、`refactor`、`docs`、`chore`、`research`。
- linked worktree 中会写公共 Git 目录的命令（fetch、worktree add、commit、push -u、设置 upstream），统一经参数文件给出的包装器执行。被沙箱拦截是权限问题，不代表仓库损坏。
- 同一工作区同时只有一个写入者：开发交审时停写，审查结束取证后才交回。
- 遇到归属不明的改动，保留原状并报告。

## 提交

- 暂存和提交只点名本任务的路径。
- 标题写 `<type>(<scope>): <具体结果>`。提交用 `feat`，分支前缀用 `feature`，两者不要混用。多文件或非机械改动，正文写 `变更：`、`原因：`，各一两句；验证事实写在 PR 里。
- 截图、日志、trace、取证报告放任务临时目录，只有结论进 PR；任务完成且无占用后清理。

## PR

- 创建 PR、更新正文、修交付证据、转 Ready，都交给参数文件指定的交付 Skill。
- 先建 Draft 交独立审查；参数文件规定的分级例外可直接 Ready。
- 正文按仓库模板写。校验和发布用同一个文件，CLI 用 `--body-file`。
- 新提交不会把已 Ready 的 PR 改回 Draft。PR 只保存交付结果和版本化证据；CI、审查、进度以平台原生记录为准。

## 证据与 CI

先用已有证据，只为真实缺口补跑。push、改正文、切换状态都不是重跑的理由。证据怎么判、CI 怎么请求，按参数文件。

## 审查闭环

- 独立复核由与实现分离的上下文用 `pr-review` 完成，绑定一个完整 SHA。开发用 `implement` 处理发现并发 FIX-REPLY，审查方对完整增量复核。
- REVIEW、FIX-REPLY、RECHECK 的格式只有一个来源：`pr-review` 的 `structured-review-output`。正式结论只留在原 PR 评论里；版本写完整 SHA，来源写评论永久链接。
- 启用 `agent-message` 时，同一任务内开发与审查的交接，以及跨任务通知，都按它发消息。消息只做交接，不复制结论。

## Ready 与合并

- Ready 只核对证据和状态，不启动测试。转换后回读：非 Draft，且 head 未变。
- 合并：
  1. 固定已核验的 head，跑合并前门禁。
  2. 向用户告知六项：分支、PR 状态、审查状态、CI 状态、合并方式、是否删远端分支。
  3. 执行 `gh pr merge <PR> <合并方式> --match-head-commit <已核验SHA>`。默认普通 merge，保留提交历史；只有用户明确选择时才 squash。
  4. head 变了就重新取证，不能把变量换成新版本直接重试。

## 同步与冲突

- 主工作区更新主线只用 fast-forward。失败说明本地主线有人提交过，停下报告。
- 任务分支是否同步主线，看真实冲突和输入影响，不看主线是否前进。已推送或共享的分支用普通 merge，保留历史。
- 冲突先核对双方意图，只处理本范围内能确定的取舍；定不了的，暂停受影响部分，交参数文件指定的责任方。

## 回收与破坏性操作

- **远端分支回收**：先刷新远端，确认合并提交和原 PR head 都能从主线到达，且远端分支没有新增提交，再删除并回读确认。不用“同时删本地分支”的选项。回收远端不等于可以删本地 worktree。
- **本地清理**：确认无开发、审查、验收占用，工作区 clean，分支没有未合并的独有提交，再在授权范围内清理。可复用环境、他人改动和仍需验收的证据都要保留。
- **破坏性操作默认先停下、报告、等用户确认后再执行**，项目授权另有例外时从其规定。范围包括：
  - `git reset --hard`；
  - `git checkout -- <path>` / `git restore`（丢弃改动）；
  - `git clean`；
  - 删除未跟踪或未提交的文件；
  - 强推；
  - rebase 已推送分支；
  - 删除其他分支；
  - `git worktree remove / prune / move`。

  报告写清：当前状态、风险、可选方案、推荐方案、需要确认的命令。
- 合并后发现问题，走修复 PR 或 revert PR，不直接在主线上修补后推送。
