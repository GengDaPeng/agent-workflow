# 代码质量基线

Standards 轴在仓库自己的编码规范之外，总带上这份基线。它只回答一个问题：**这段改动会让谁、在什么情况下出错，或者让下一个改代码的人改错？** 说不出具体后果的，不报。

- **仓库规范优先。** 仓库明文认可的写法，基线不再标记。
- **基线只给判断。** 每条命中写成“可能是 X”，引用 hunk，说明可达后果；工具已经拦截的不报。

## 坏味道

Fowler《重构》第 3 章的坏味道。每条是“是什么 → 常见改法”；后果成立时才给改法。

- **Mysterious Name**：名字看不出它做什么、装什么。→ 改名；起不出诚实的名字，说明设计本身含糊。
- **Duplicated Code**：同一条规则的逻辑出现在多处，改一处会漏另一处。→ 抽出共用。
- **Feature Envy**：方法读别人的数据比读自己的多。→ 移到数据所在的地方。
- **Data Clumps**：几个字段或参数总是一起出现。→ 合成一个类型。
- **Primitive Obsession**：用字符串或数字代表有规则的领域概念，混用或绕过校验没人拦。→ 给它自己的类型，在输入边界收窄。
- **Repeated Switches**：同一个判断在多处重复。→ 收到一处（映射表或多态）。
- **Shotgun Surgery**：改一条规则要同时动好几个文件。→ 把一起变化的代码收进一个模块。
- **Divergent Change**：一个文件因为几种互不相关的原因被修改。→ 拆开，各管一种变化。
- **Speculative Generality**：为当前没有的需求加的抽象、参数或钩子。→ 删掉，等真有需要再加。
- **Message Chains**：调用方一路 `a.b().c().d()`，依赖别人的内部结构。→ 在第一个对象上提供一个方法。
- **Middle Man**：只转手调用、不承担边界或适配的层。→ 去掉，直接调用目标。
- **Refused Bequest**：实现方不兑现所继承接口的承诺。→ 改用组合。
- **Comments**：注释复述代码在做什么，或写着会过时的规范编号、过程记录。→ 让代码自己说清（改名、抽函数），删掉注释。只说明代码表达不了的原因（外部限制、不明显的约束、临时绕行及何时撤掉）的注释保留。

## 坏味道看不出的风险

- **类型边界**：`any`、类型断言或重复定义的 DTO 掩盖了真实数据形状，错误到运行时才暴露。
- **信任边界**：授权只在前端做；敏感数据进了日志、缓存、导出或错误信息；HTML、URL、文件名等外部输入没按来源净化。
- **状态与并发**：回调捕获旧值；退出、卸载或切换身份时没清理；重复执行、乱序覆盖、部分成功。
- **失败路径**：错误被吞掉；空、加载、出错、无权限时拿旧数据冒充成功。
- **界面**：控件缺可访问名称或键盘路径；信息只靠颜色表达；样式写死颜色、没用主题 token。可用 [`../scripts/no-hardcoded-color.mjs`](../scripts/no-hardcoded-color.mjs) 查改动文件，非零只表示需要人工判断。

测试改动由 `tdd` 的 `test-design` reference 判断，不在本基线内。
