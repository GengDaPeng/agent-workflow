# 通用代码质量审查

代码变更的 Standards 轴每次都覆盖本基线的十二项结构线索与其余适用检查，不以已经怀疑某项风险为前提。当前版本已在上下文中时可复用，无须重复复制或读取；分组审查共同覆盖完整范围。覆盖不要求每项都产出 finding 或触发重构；项目业务规则和技术约定仍由当前仓库的正式 owner 决定。

只报告 changed code 中可达且有具体后果的问题。通用镜头属于判断项；正式规则才能形成硬违规。跳过工具已经稳定阻断的格式问题，也不因个人偏好或抽象的“最佳实践”报 finding。

## 结构线索

下列 Fowler code smells（代码异味）只帮助提出问题；先确认实际后果和现有约束，再决定是否修改，不从名称直接推导抽取、拆分、重命名或引入抽象。

- **Mysterious Name**：命名是否让调用者误解真实职责。
- **Duplicated Code**：相似逻辑是否承担同一规则，已经产生或可能在可达路径产生分歧。
- **Feature Envy**：跨对象读取是否绕开真正的 owner。
- **Data Clumps**：成组数据是否具有必须共同维护的不变量。
- **Primitive Obsession**：原始类型是否允许混淆不同语义或绕过边界验证。
- **Repeated Switches**：多处分支是否重复拥有同一决策。
- **Shotgun Surgery**：同一规则是否散落到必须同步维护的多个位置。
- **Divergent Change**：同一模块是否承载互不相关、相互干扰的变化。
- **Speculative Generality**：额外能力是否缺少当前任务或真实消费者。
- **Message Chains**：调用者是否依赖不属于其契约的内部结构。
- **Middle Man**：转发层是否承担必要的边界或适配责任。
- **Refused Bequest**：实现是否违背调用者依赖的接口或继承契约。

## 边界与结构

- 类型是否在输入边界收窄并复用既有模型，还是用 `any`、重复 DTO 或断言掩盖真实形状。
- 错误、权限、状态和数据边界是否归实际 owner，调用方是否绕过或复制 owner 判断。

## 注释

编写、维护与审查说明性注释时，以当前代码、调用方、正式 owner 和可核实的外部限制判断其独立信息价值：

- 简短说明代码难以表达的设计原因、非显然不变量、接口／数据语义或外部限制；事实和规则引用到当前 owner。
- 删除复述代码、陈旧过程记录、无效分隔装饰、已失效待办和被注释掉的废弃代码；过时或误导的说明按当前事实纠正。有用说明留在相关代码旁。
- 临时绕行说明当前原因、适用边界和退出条件；当前做法本身不构成其他入口复制它的理由。有效待办保留可追溯的未完成目标，不凭 TODO、版本号或 workaround 字样决定去留。
- 许可证、shebang、编译／打包／类型／lint／覆盖率指令及正式数据库注释按各自合同维护。无法确认是否过时或被工具消费时保留并说明疑点；发现真实缺陷交当前任务的范围处置流程。
- 完成清理时说明覆盖范围及代表性的删除、改写、保留理由，用适用解析、编译或等效证据核对可执行语义，并单独核对机器指令和正式说明；按实际影响运行轻量检查，不以注释数量或删除比例衡量成果。

## 生命周期与数据流

- Hook、事件回调、订阅和异步任务是否捕获旧值，是否在退出、切换身份或卸载时正确清理。
- Query、store、缓存和本地状态是否各守 owner；key、失效、取消、重试和身份切换是否可能保留或覆盖错误数据。
- 并发请求、事务、队列或写入是否存在重复执行、乱序覆盖、部分成功、吞错或不可恢复失败。

## 信任边界

- 前端展示控制是否被误当成授权；后端或可信边界是否仍执行最终校验。
- 敏感数据是否进入不必要的展示、持久缓存、日志、导出、剪贴板或错误信息。
- HTML、Markdown、iframe、文件名、跳转和下载 URL 等外部输入是否经过与来源匹配的限制或净化。

## 运行行为与成本

- 正常、空、加载、错误、过期、无权限和恢复路径是否都保持一致，不用旧数据伪装成功。
- 订阅范围、渲染期计算、大列表和依赖引入是否造成可解释的重渲染、阻塞、重复请求或 bundle 成本；没有具体影响不报告。

## 可访问性与视觉契约

- 交互控件是否有可访问名称和键盘路径，焦点进入、退出及恢复是否可预测。
- 状态、错误和必填信息是否只靠颜色、placeholder 或 Tooltip 表达；表单错误是否关联真实字段。
- 截断内容、图标操作和动态提示是否仍向辅助技术提供等价信息。
- 样式是否复用主题 token；检查 changed code 时可运行 [`../scripts/no-hardcoded-color.mjs`](../scripts/no-hardcoded-color.mjs)，把 changed code 路径作为位置参数或 `--changed-files` 清单传入。脚本非零只表示需要人工判断，不是 CI gate；主题定义或明确的视觉资产可保留。

## 测试证明

- 测试是否经过真正拥有行为的组件树、observer、事务、队列或外部边界，而不是只调用旁路函数或 mock 内部实现。
- 判断测试选择时调用 Skill 工具：`tdd`，读其 `test-design` reference；追加证明层或设施时读其 `verification-stop` reference；审查覆盖增量价值、重复证明与可达风险，按当前仓库测试政策核对 CI 准入。并发或恢复命题核对决定结论的事件顺序与失败断言。
