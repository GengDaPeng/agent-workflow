# 任务卡

一个需要派发或持续跟踪的执行任务，由一个 Open Issue 和它唯一的置顶任务卡评论承载。能完整解决原子 Issue 时直接复用；多步父路线不发卡，每个实际开工的步骤用独立子 Issue。多个来源合并为一个任务时只建一个任务 Issue，回链来源。

## 格式

```md
评论者：<项目>-<模型ID>
[TASK-CARD]
Task: <任务编号>
Grade: B级 | A级 | S级

## 完成条件
## 范围
## 不做
## 正式依据
## 验证
## 前置 / 阻断
```

| 栏目 | 写什么 |
|---|---|
| 完成条件 | 一句交付命题，加至多五条可观察、可核验的结果；有界面变化时写用户会看到什么 |
| 范围 | 允许改变的对象、行为和责任边界，以及必须联动的消费者或接口 |
| 不做 | 相邻但不属于完成条件的能力；已确认的范围外问题链接 Issue |
| 正式依据 | 实际使用的规范编号与章节；引用，不复制 |
| 验证 | 必须成立的结果、关键反例和受影响边界 |
| 前置 / 阻断 | 开工依赖，以及会改变范围、事实源或授权的停止条件 |

- 冻结问题，不冻结答案：不写文件清单、实现步骤或候选方案。整张卡两分钟读完。
- 稳定规则回正式负责方；本任务依赖但尚未回写的结论，列为前置或把回写纳入完成条件。
- 模型、会话、工作位置、并行安排、联系人和交付出口放派发记录，不进卡。

## 立卡与派发

1. 确认 Issue 已接受、目标可独立验收、前置成立。
2. 有唯一置顶任务卡就编辑同一条，没有就新建并置顶；多张并存先收口成一张。置顶评论的深链接即 `task_url`。
3. 按参数文件做状态同步并回读确认。
4. 立即派发时，直接用参数文件的派发命令，它内置任务卡校验；只核卡不派发时，单独跑校验命令。两者不连续执行。

开工后，开发、审查和 PR 只消费同一 `task_url`；分级只从卡上读，派发和 PR 不覆盖。后续开发、恢复和审查不逐步重跑开工检查。

## 调整与收尾

- 调整：编辑同一条置顶评论，另留一条普通评论写实际变化和原因，再通知受影响的执行者。不用本地旧副本覆盖线上正文。
- 收尾：回链 PR、复核和正式落点。来源 Issue 全部完成就按 tracker 关闭；仍有真实剩余范围时，取消本轮任务卡置顶，按参数文件恢复状态，回读一致后留本轮完成评论，不把来源 Issue 整体报完。
- 任一步写入失败，保留同一张卡和已确认的结果，从第一个未完成步骤补齐，不建替代卡。立卡未确认一致不派发，收尾未确认一致不宣告收口。
