# 代理指令审查方法

本方法审查 Skill、`AGENTS.md`、`CLAUDE.md`、代理指针和 reference 是否能稳定触发并完成预期过程。它不审查业务语义、代码工程质量或 Git / PR 状态。

先固定被审对象、版本或 working-tree diff，以及它声称要产生的执行行为。作者说明只是待核主张；没有 PR 不影响审查。

被审改动新增、迁移或升格 agent harness 的规则、共享合同、脚本、Hook、checker 或 gate 时，先读取 [`harness-placement.md`](harness-placement.md)，核对其 owner 与形态是否成立。

## 重建调用与执行图

从用户或其他 Skill 可能发出的真实请求出发，检查：

- description、显式调用和上游路由能否覆盖每个应触发分支，又不会吞掉无关任务；
- 主步骤、条件分支、reference 和完成条件是否可达，是否存在循环调用、提前结束或无人承接的出口；
- 多个 Skill 协作时，输入、输出、自审、独立复核和授权责任是否只有一个 owner。

## 核对指针与真相源

沿每个 context pointer 走到实际目标，检查触发措辞、相对路径和目标内容是否匹配。每种含义只由一个 owner 定义：Skill 可以拥有可复用方法，业务和项目规则回到正式规范；项目适配只保留必要路由与接缝，不复制规则正文或可由环境直接读取的事实。

涉及评论、Issue、commit、push、PR、任务状态或正式文档写入时，确认指令没有把分析授权扩大成外部写入，也没有让子代理越过主代理直接发布结果。

## 运行负向检查

对删除、重命名或迁移的 Skill、reference、命令和术语搜索旧入口；检查未改文件中的死路径、相互矛盾的重复规则、过期 cache、第二真相源和不再可达的 reference。新增指令还要判断它是否改变默认行为；不改变行为的 no-op 应删除。

## 输出

按发现项输出问题、影响、证据和最小修法。引用项目规范时，按项目参数文件 [`docs/agents/review.md`](../../../../docs/agents/review.md) 规定的证据要求给出依据；没有该参数时，给出原文或两处矛盾位置；没有正式依据的判断明确写成待裁决。审查只报告发现，不在同一动作中顺手修复。

完成标准：每个实际触发分支都有唯一入口、可达过程、明确完成条件和合法输出；每个指针都能到达当前 owner；删除和迁移没有留下活动旧路径。
