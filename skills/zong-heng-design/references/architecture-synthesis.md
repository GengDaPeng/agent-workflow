# D3 架构综合

主流程判定 D3 后读取。核心模型和存在性裁决以主流程为准；本文件把已成立的设计展开到运行、部署、演进和证明。工作地图是唯一结构底图，这里不复制对象、关键边或负责方；结构主张找不到地图落点时先更新同一份地图。

## 1. 提炼架构驱动因素

只收会改变架构的核心场景、可度量的质量属性、部署 / 法规 / 外部生态 / 资源 / 运维硬约束，以及会推翻核心决定的未知项。质量场景写成“来源、刺激、环境、受影响对象、响应、可度量标准”。

**完成条件：**每个驱动因素指向至少一个架构决定。

## 2. 迭代架构决定

只为会改变负责方、边界、不变量、质量目标、部署、迁移或回滚的未决问题维护一层决策覆盖：

| 决策 | 地图对象或关键边 | 驱动因素 | 依赖的决策 | 结论与证据 | 状态 |
|---|---|---|---|---|---|

只有 A 的答案会改变 B 的合法候选，或 B 必须等 A 时，才记 `A → B`。每轮选依赖已关闭且风险最高的决定，复用主流程第 6 步的候选比较，把结论传播到后续决定并删掉不再成立的问题；发现冲突回到最早的错误决定，不加补偿掩盖。每轮收敛后复核有没有正式依据冲突、无人有权裁决或需要用户改变产品目标。

**完成条件：**每个活动决定都有地图落点、驱动因素、依赖、状态和证据；剩余问题不再改变负责方、边界、关键质量属性、部署或实施拆分。

## 3. 只画必要视图

视图是地图针对一个问题的投影。先写问题，再选最小投影：

| 问题 | 视图 |
|---|---|
| 外部参与者和责任边界在哪 | 系统上下文 |
| 负责方、模块和依赖如何分布 | 静态结构 |
| 关键场景怎样到达结果和恢复 | 运行时序、状态或事件流 |
| 进程、网络和设施怎样承载运行 | 部署视图 |
| 事实、写入权、投影和迁移怎样流动 | 数据与真相源视图 |
| 权限、审计、错误和可观测性怎样一致落地 | 横切策略 |
| 旧系统怎样进入目标状态并安全退出 | 演进、迁移与回滚 |

每个视图标明回答的问题、用到的地图对象或关键边、支持的决定和非证明边界。C4 只在其某一层级能直接回答问题时用，一个视图一个抽象层级。没有问题就不画。

## 4. 后置评估

可用 ATAM 或 Well-Architected 作遗漏探针：沿真实运行和部署路径施压，区分当前证据和假设。它们不替代第一性建模，也不直接推出新机制；本轮新增的机制再过一遍主流程第 2、3 步。发现风险时先删错误自由度或修正最早的决定。

## 5. 追加交付

在核心裁决包后只追加实际命中的：驱动因素与决策依赖；必要视图；部署、故障、恢复、迁移和回滚；高风险主张的 oracle、证伪条件和非证明边界；应回写的正式负责方、实现接缝和后续任务边界。
