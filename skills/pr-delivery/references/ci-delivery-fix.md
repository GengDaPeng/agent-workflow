# CI 等待与交付门禁失败

## 等 CI

先确认当前候选已按参数文件显式请求 CI；没请求时等候选稳定再请求，不是每次 push 都请求。等待时把刷新输出写进日志文件，结束后只读一次结果：

```bash
gh pr checks <n> --watch --interval 30 --fail-fast > <日志文件> 2>&1
```

不用管道截断，避免丢失退出码。失败时按需读相关日志片段。

## 门禁失败

先固定 PR、current head 和失败命令，用同一输入重跑并保留原始输出。只改失败输入的负责方：

| 失败来源 | 处理 |
|---|---|
| 标题、正文、Verification | 本 Skill 修正，重跑原门禁 |
| base、分支、HEAD、dirty、推送状态 | `git-workflow` 的对应阶段 |
| 实现、测试或产物缺失 | 调用 Skill 工具：`implement`，完成后重新交付 |
| 缺可继承的复核，或语义上需要复查 | 保持 PR 状态，交 `pr-review` |
| 任务卡或分级错误 | 停止，交任务卡负责方 |
| `gh` 认证、网络或权限 | `git-workflow` 的“证据与 CI” |

只有目标门禁对 current head 通过，才算该阻断解除；不用另一条较弱的命令代替。
