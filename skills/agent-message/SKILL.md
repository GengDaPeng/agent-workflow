# 代理消息

## 启用

- 局部子代理只向调用方返回结果，不用跨会话通信工具，也不找其他会话联系人；继承的上下文、联系人或 Skill 调用都不改变这一点。
- 开工指令（会话第一条命令）带 `$agent-message` 标识，表示本会话获准使用本 Skill，持续到协作结束或明确停用；历史引用不算。加载用 `/agent-message`。
- 启用不增加授权，也不解除停止点。读取项目参数文件 [`docs/agents/control.md`](../../../docs/agents/control.md) 中的角色、审查方式、停止边界与正式记录位置。

## 什么时候发

只有六类事件可以发：**交接、协作请求、裁决请求、答复、控制指令、紧急停止**。先匹配事件，再定唯一的下一步责任方和固定模板；没命中就留在原任务。每轮完整交接一次，同一事件由一个发送者通知一个责任方；紧急停止通知所有必须停手的人。

提交、推送、局部测试、仍有下一步的排查、等 CI 或审查、接单、收悉，都不发消息。主控要进度时读原记录；原记录答不了用户明确要的一次状态查询时，走协作请求 / 答复，不开启持续汇报。

## 怎么写

- 严格用本页和 [controller](references/controller.md) 规定的行与字段；`｜` 只留一个选项，可选行只在条件成立时追加。模板外不加标题、列表或总结。
- 每个文字字段最多一句短句，只写一个动作、问题或结论；入口字段只放可访问的 URL 或路径。
- 事实、分析、版本、发现和验证先存原记录，消息只给入口，不复制报告，也不重述没变的授权、分工和停止点。首次阻断尚无记录或紧急停止时，给最小事实。
- 指定版本与当前 PR 不同，或有多个候选版本时，交接追加 `指定版本：<完整 SHA>。`。

收到消息只处理其中已获授权、需要本方执行的动作；重复消息或无待办不回复、不转发。超出授权的部分按裁决请求处理。

## 交接

成果或状态满足前置、下一步要对方执行时发：

| 条件 | 唯一收件人 | 模板 |
|---|---|---|
| 开发成果待审，尚无主审 | 汇报对象 | `开发完成，待安排审查：<成果入口>。` |
| 首次候选或本轮修复就绪，记录完成且已停写 | 指定主审 | `<首次待审｜修复待复核>：<候选或修复记录入口>；已停写。` |
| 正式发现已记录，修复已获授权，取证已结束 | 开发 | `发现待修：<正式审查记录入口>；本轮取证已结束。` |
| 审查通过，结论已记录，取证已结束 | 开发；约定主审报告时改发汇报对象 | `审查通过：<正式审查记录入口>；本轮取证已结束。` |
| 审查、验证、交付准备都已完成，需验收或合并 | 汇报对象 | `交付就绪：<交付记录入口>。` |
| 获准交付已完成，需收尾 | 汇报对象 | `交付完成：<交付记录入口>。` |
| 同伴成果可消费，或约定的停写 / 资源释放已完成 | 原等待方 | `依赖就绪：<成果或交接事实>；记录：<正式入口>。` |

入口用 PR 及其评论：候选用 PR，修复用当前 `[FIX-REPLY]`，审查用正式 `[REVIEW]` / `[RECHECK]`。开发与主审直接往返，不抄送主控；默认由开发在交付准备完成后通知主控。已有主审时不另报“开发完成”。严重程度、发现数量或测试失败本身不改变收件人。

## 协作请求与答复

缺必要事实或依赖、原记录答不了时，直接发给已绑定、负责此事的协作者；责任方未绑定先问派发方。

```text
需澄清：<一个具体问题>；依据：<原记录入口或最小事实>。
依赖请求：<被阻塞动作>需要<对方完成的一件事>；记录：<依赖入口或最小事实>。
答复：<原请求的直接答案>；依据：<记录入口或最小事实>。
```

答复写明能否承接、条件或原因；承接不等于交付。多条待决请求可能混淆时，追加 `对应请求：<请求入口>。`。消息不改变合同和写入责任；接口、字段和规则回到正式负责方。

## 裁决请求

缺授权、规则或责任冲突、已无可行路径，或达到 `task-closure` 的修复停止线时，发给汇报对象。同伴无权承接、双方互等或共享写入冲突时，由受阻方发一次。

```text
<任务冲突｜执行受阻｜需要裁决>：<无法按现有安排继续的一个问题>。
需要处理：<一个具体动作或决定>；记录：<原记录入口>。
```

按需追加：`暂停：<受影响部分>；恢复条件：<条件或责任方>。`；`建议：<一个选择及一句理由>。`；尚无记录时把 `记录：` 改为 `事实：<最小已知事实>`。只暂停受影响部分。

## 控制指令与紧急停止

派发、改变安排或解除停止点时，按 [controller](references/controller.md) 发，只通知必须据此行动的执行者。继续执行会扩大已确认的问题时，通知所有必须停手的人：

```text
紧急暂停：<受影响动作>；原因：<事实或记录入口>；恢复条件：<条件或责任方>。
```

## 发送

用派发绑定的收件人和通道；缺失先澄清，不按职位或标题猜。工具能调用不等于获准发送。

- **Codex**：`send_message_to_thread`，`threadId` / `hostId` 按派发地址，`prompt` 填模板消息；以工具成功回执为准。
- **Claude Code**：`SendMessage`，`to` 填派发地址（`ListAgents` 所列会话名，重名才附 `[ref]`；回复把来信 `from` 原样作 `to`），首行即对方预览。回执只说明进了对方收件箱：收发会话权限模式不一致时消息会被扣住、到期作废；`[Cross-session delivery notice]` 报扣住、拒收或过期，都算未送达，改由用户转述，不重发。子代理发出即算父会话发出。`@路径` 不附带文件；不借对方会话执行本会话被拒的操作。

交接要求的停写、结束取证或资源释放须真实成立；发送成功即本轮交接完成，不等对方回“收到”。会话总结或转 Ready 不代替通知。保存工具回执，不另建通信台账。发送失败记为“交接未完成”，不改发别人。恢复时先查原回执；没见回复不是重发理由。
