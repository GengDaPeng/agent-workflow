# 失败反例

已闭环审查中反复出现的失败模式。两向答题完成后用来攻击已有结论，不是风险分类表，也不替代正式规范。

**回补**：只收阻断 / 严重级、已修复复核或用户裁决的根因，跨改动复现优先；按错误模式合并，正文不写来源与项目名，脱离历史也能直接行动。格式为识别信号 / 原问题 / 本质错误 / 审查动作，最多 12 条。只对一个项目成立的反例放进该项目参数文件给出的项目探针；能在开工前消除的根因另交项目的设计方法回补。

## 1. 把目标、物理存在或仅测试可达写成当前事实

识别信号：地图或报告写“当前 / 已对齐 / 已闭环”，证据却只有 schema、没有生产调用方的服务、测试入口、读取侧、计划中的任务或旧版本记录。

原问题：生命周期核验把物理字段与缺失的写入者一并判定为对齐；一个停用方案把仅导出的服务和测试专用路由当作生产链；升级地图继续引用已删除的机制和旧版本的通过结论。

本质错误：载体存在、代码可调用、测试可执行、生产启用、目标已设计是五种证据状态，不能互相替代。

审查动作：逐节点标 `CURRENT / TARGET / PHYSICAL_ONLY / TEST_ONLY / NON_PROOF`；从正式触发点追到写入者、消费者与事务外回读；地图未绑定精确版本时下调结论。

## 2. 用替代通道或替代环境证明正式命题

识别信号：正式发布走部署命令，测试却直接执行 SQL；升级证明使用全新数据库；生产链应走公开路由或调度器，测试却直调服务、手改状态或只测协议入口。

原问题：直连执行能保留迁移诊断，正式部署命令却把它吞掉；“升级后纵切”实际运行在新库；测试消费者没有走公共状态机；一个入口返回不可用，被扩大成全部写入者零写入的证明。

本质错误：执行通道、数据世代、入口和编排本身就是命题的一部分；替代接缝只能证明另一个命题。

审查动作：固定“主体—正式入口—数据世代—编排—结果”；负例走同一部署、升级、路由或调度通道；意外连到新库或绕过正式入口时测试必须失败。

## 3. 失败转换没有阶段化安全终点

识别信号：多阶段转换会开启入口、改写外部状态或创建资源；失败分支没有按发生阶段映射到负责方定义的安全终点，或失败后没有从事务外回读入口、状态与残留资源。

原问题：身份生命周期命令返回失败后，认证入口、核验标记或容器仍保持运行；数据库迁移失败后留下错误的迁移账本且诊断丢失。

本质错误：成功和每个失败阶段是不同生命周期；安全终点可以不同，但都必须由负责方定义、可观察且可恢复，退出码、回滚和测试转绿不能替代该事实。

审查动作：在不可逆写入前后、证据处理和清理阶段分别注入失败；事务外回读入口、凭据、账本与资源，确认每个分支到达负责方定义的停止、回滚、保留、隔离或销毁终点，并让失败覆盖原成功码。

## 4. 读后判断与最终写入没有绑定同一事实集

识别信号：评估只返回已知条目的摘要或版本标记；服务先读关系后另行写入；没有集合版本、共享栅栏、CAS、串行键或完整重评。

原问题：评估完成后新增的关系、事实或任务仍可漏过；分配使用了已失效的证据；同一租户的两个聚合可以并发提交出非法时间线。

本质错误：不变量约束提交时的完整集合；逐项版本发现不了幻影新增、删除和兄弟写入者。

审查动作：在读写之间插入新增、删除、转移和并发写；冲突必须零业务效果；核对所有候选生产者是否进入完整重评、集合版本、栅栏、CAS 或等价冲突边界。

## 5. 有失败状态，却没有可操作终点

识别信号：存在 `FAILED / DEAD / REQUIRED / UNRESOLVED` 一类状态，但没有授权查询、责任人、有界重试、接管、关闭 / 跳过 / 升级、告警或持久的尝试记录；人工关闭还复用不真实的终态。

原问题：消息发布记录进入死信后，操作者只能凭已知 ID 重试，无法查询失败列表；进程在异常捕获前连续崩溃会绕过重试上限；跨模块回写首次失败不生成可恢复的尝试记录；未解析项只增加计数而没有处置对象。

本质错误：状态值不是生命周期；失败对象只有“可发现—可归责—可恢复—可真实关闭—可审计”齐全才有业务终点。

审查动作：从责任人入口反查列表、授权、预检、重试上限、接管、终态、审计和告警；验证未知 ID 可发现、耗尽后停止副作用、人工终态保留原失败。

## 6. 新版本建立，旧任务、令牌和载体未退役

识别信号：已有新键、新权限版本、新字段、新凭据或正式裁决，旧的待处理 / 重试任务、令牌、环境变量、任务单、路径或消费者仍能运行。

原问题：新版通知不取消旧版的待投递、重试任务和旧链接；身份服务换新流程后，旧管理凭据文件仍留在磁盘并注入容器；正式裁决完成后，活动任务单仍保留相反的候选方案。

本质错误：替换必须同时“启用新版本 + 终止旧版本能力”；否则系统存在两个有效真相。

审查动作：扫描旧的写入者、读取者、作业、令牌、fixture、密钥载体、任务单和入口；覆盖待处理、失败重试、已交付和历史引用；要求失效、重绑、取消、退役，或明确写成不证明边界。

## 7. 销毁动作没有先取得资源身份与所有权

识别信号：接受外部传入的资源名；确认本轮所有权前就注册破坏性清理；清单查询失败被当作空集合；关闭出错即停后，所有权断言失败仍执行停止、删卷或删除；没有按证据保留、敏感度和恢复责任裁决保留、隔离或销毁。

原问题：同名编排项目碰撞后，退出清理反而删除了既有数据卷；标记或令牌失效仍可触碰他人资源；证据还没采集和扫描就先销毁。

本质错误：清理是高权限写操作；只有持有稳定身份、原子所有权凭据和成功回读的执行者才有权销毁。

审查动作：注入清单失败、资源已存在、标记缺失和令牌不匹配，证明均无破坏性动作；按证据保留、敏感度和恢复责任核对保留 / 隔离 / 销毁终点，命中采集或扫描义务时再注入其失败；销毁必须先证明所有权，并回读确认已不存在。

## 8. 组合输出没有绑定同一集合命题、计量单位与事实负责方

识别信号：同一响应或导出的计数、条目、分页、状态各自组装过滤条件、计量单位或状态来源；字段称“人数”却按关系行计数，收窄的筛选只作用于部分字段，一个故障域的状态又替代了另一事实的负责方。

原问题：同一人拥有多条关系行时人数被重复计算；请求加上收窄的分组筛选后，名单按分组缩小而统计仍覆盖全部范围；一个发布事件的消费者任务状态被误当成事件本身的发布状态。

本质错误：组合输出没有声明各字段回答的集合命题、计量单位、事实负责方及字段间约束；声称同口径的字段没有绑定同一命题时，每项局部计算都可能正确，整体仍矛盾。

审查动作：逐字段声明集合谓词、计量单位和事实负责方，再核对计数 / 条目 / 分页 / 状态 / 导出的关系；只对声称同口径的字段要求回答同一命题，共享查询条件或负责方投影只是一种实现，不得用消费者状态替代负责方状态。构造一人多关系、宽权限加窄筛选、一个事件多消费者的恒等式反例。

## 9. 共享不变量只修当前入口，兄弟路径继续旁路

识别信号：身份、状态、口径或审计等共享不变量的修复只覆盖已知报错入口；同类生产者、写入者、消费者、第三方调度器、请求与响应出口没有进入同一份出现处清单，测试只模拟公共守卫或直接调用回调。

原问题：会话安全屏障按切换身份 / 退出、到期清理、上下文写入、旧代际的成功 / 失败响应逐轮补洞；局部测试每轮转绿，真实的页面聚焦 / 联网调度生命周期仍能从兄弟入口绕过同一屏障。

本质错误：共享不变量由多个入口和框架生命周期共同决定；局部守卫只保护一条路径，未被枚举的兄弟路径仍保留违反不变量的能力。

审查动作：固定不变量和唯一负责方，枚举全部生产者、写入者、消费者、第三方调度器与请求 / 响应出口；用真实框架生命周期做负向时序探针，只有兄弟路径零残留才算根因闭环。
