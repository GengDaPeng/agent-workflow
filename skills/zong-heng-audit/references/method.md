# 纵横审查方法

L1 的输入是单一对象锚点（对象、负责方、不变量、生命周期、失败 / 恢复边界），L2 / L3 的输入是 `map-semantic-units` 的版本绑定工作地图。两者都是待证主张：证据显示身份、生命周期、不变量、权限归属或失败 / 恢复行为与之不同时，返回 `MAP-CHALLENGE` 或覆盖缺口。

路线决定看哪里，视角决定在每个点上必须问出什么。

## 答题规则

- **答案是具体物**。每个视角的答案只能是可核对的东西：一个次数表达式、一个名字、一处代码位置、一次真实运行的输出。“已检查”“未发现问题”不是答案。
- **视角不成立也要答**。写出使它不成立的那个事实和位置，例如“无绕行：三个调用点都经过同一包装，位置……”。
- **答不出记缺口**。写明卡在哪一跳、缺什么证据，不并入通过。
- **先推后读**。读实现之前，先从任务与正式依据写出正确实现在各视角下应有的答案，再读实现对照；两者的差是发现的起点。只读实现再点头，等于让作者替你定了答案。
- **先挖重点节点**。不可逆的、被多个入口共享的、次数随数据放大的、与同类做法不同的节点，逐视角全问；其余节点答必要与数量。

应有答案、实际答案和缺口都记进**覆盖索引**：审查笔记里“审了哪些纵切和单元、每个视角答了什么、证据在哪、还缺什么”的对应关系。它从锚点或地图展开，供派单、验收和复核共用，格式见 [输出合同](output-contracts.md#覆盖索引)；它不是另一份地图。

## 纵向：一次执行，从触发到可观察结果

一条纵切是一条业务命题：谁或什么触发、在什么前置状态下、系统必须形成什么可观察结果。从任务目标、正式规范、参数文件给出的旅程来源和地图的关键边反推受影响纵切；没有现成旅程时只建本轮用的最小临时纵切。回写目标、状态流转或跨域协作链实质不同才拆成两条。

```text
触发者 / 事件 → 主体、上下文与前置条件 → 负责方裁决
→ 状态转换与事务提交 → 异步交接 / 外部调用
→ 最终业务事实 → 下游可观察结果 → 证据与证明
```

目标纵切始终写完整命题；当前交付片段标出本次改动实际负责的起止点。只沿真实存在的链路取证，不用模拟、临时回调或未来设计补成闭环。测试须从真实入口经过真实负责方、事务和调度边界到达终点；直接调内部回调或从中段开始只证明局部片段。只有真实链路到达可观察终点，才能认定端到端闭环。

把纵切拆成跳：一次调用、一次存储访问、一次状态转换或一次交接各算一跳。逐跳回答：

1. **必要**：这一跳产出的东西被谁用掉？交出消费它的下一跳或最终结果的位置。没有消费者，或只被用掉一部分，就是多做的工作。
2. **数量**：这一跳在一次触发里执行几次？交出次数表达式（1 次 / 每行 1 次 / 每行 × 每动作 1 次），并指出乘数来自哪个集合、真实规模下多大、上界在哪。跨进程、访问存储、加锁或写入的跳，次数随数据增长时要有依据。
3. **持有**：这一跳在哪个事务、快照、锁、连接或会话里进行？交出取得它的跳和释放它的跳，列出持有期间等待外部的跳，并判断隔离级别与锁粒度是否与这一跳的读写性质相称。
4. **归责**：链上每个判断（权限、校验、不变量、统计口径）最终由哪一跳负责？交出那一跳；同一判断在其他跳上出现的，逐处标明是重复、假设，还是另一套判据。
5. **断点**：这一跳之前、之中、之后被中断、重复或并发执行时，事实停在哪里？交出停留位置、能发现它的人或机制、回到合法状态的路径。撤回、重开、重试、补偿和人工接管按同一问法；失败探针从关键边推导。
6. **实证**（每条纵切答一次）：这条链的结论由哪一次真实运行证明？交出那次运行的入口、数据规模、版本和装配，并逐项说明与正式链路是否相同。读代码只能证明形状（次数表达式、持有范围），量级（耗时、容量）必须有测量；没有测量时写“形状已核，量级未证”。

## 横向：同一个东西出现在多处

固定一个单元——一个事实、一条规则或一个机制——把它的全部出现处放在一起：

```text
当前活动生产者 → 负责方 → 当前合法写入者
→ 当前活动消费者与派生投影
→ 当前契约、正式表达与验证机制
→ 旧入口与退役路径
```

出现处从真实调用关系和正式计划枚举：从对象名、改动的符号、字段 / 枚举值、接口路径、旧名称和直接调用者提取搜索词，沿定义、写入、读取、缓存、客户端、测试、正式文档和门禁搜全，包括未改文件。没搜就写明理由和风险；reference 没点名某类消费者，不是跳过它的理由。区分当前活动面（代码和运行中已存在）与计划面（正式裁决过但未实现），不推测未来消费者；代码已提供却没有实际消费者的能力只算计划能力。

逐单元回答：

1. **唯一**：这个事实、规则或机制的唯一负责方是谁？交出它的位置；其余出现处逐个标明是引用还是副本，副本写出靠什么保持一致。跨域直接写入、复制公共规则、投影反向拥有事实、同一不变量的第二条写入链，都是没有同步手段的副本。
2. **穷尽**：改动触及的合同有哪些消费者？逐个列出，不抽样；每个标明仍成立、已修改或有缺口。
3. **对照**：把改动点和它的同类放在一起（同类入口、同类列表、同类写命令、同类检查）。交出同类的位置和它做同一件事的方式；这里不同的，要么指出记录在案的理由，要么记为发现。没有同类时与业内通行做法对照。
4. **兑现**：改动引用或新立的每条承诺（规范条款、裁决、预算、PR 声称、注释里的保证），由什么会失败的东西强制？逐条指出那个约束、类型、测试、门禁或告警。指不出的，这条承诺只是文字。
5. **新旧**：新机制生效后，旧入口、旧任务、旧凭据、旧常量、旧字段还能运行吗？逐个交出能否运行及依据，并指出新机制是否与某个已有机制做同一件事。
6. **绕行**：改动绕开共享包装或公共路径时，列出那层包装原本附带的全部条件，逐条说明新路径如何保住。

修复复核复用对应覆盖索引，对每个出现处标已修复、未受影响、正式推迟或仍有缺口；发现同根相邻遗漏时先扩全索引做一次零残留扫描，有未处置的当前命中就不关闭根因组。

## 缺口归类

纵向未实现片段与横向缺失的出现处用同一归类：

- 属于当前任务验收范围 → **当前缺陷**；
- 已正式推迟，且有契约、负责方和承接任务 → **不证明边界**，不算当前缺陷；
- 缺少上述承接 → **结构性覆盖缺口**。

## 交叉收敛

两向完成后检查：

- 每条纵切的裁决点和写入点是否经过横向确认的负责方；有没有绕过负责方的入口。
- 横向列出的每个当前消费者、投影或能力是否被至少一条真实纵切使用。
- 纵切结果正确时，外围契约、投影、证据或旧入口是否仍表达另一套语义。
- 两向对归属、状态含义、读写边界或完成证据是否冲突。
- 证据是否隐含 reference 没命名的生产者、消费者、失败位置、运行环境或正式表达。
- 纵向得到的次数表达式，乘以横向枚举出的调用入口数，就是这一步对全系统的实际工作量；共享步骤按这个乘积判断，不按单条链路判断。

一向通过不能覆盖另一向的阻断；交叉问题单独标记，不拆成两条。未验证项写明中断位置、缺什么和对结论的影响，不并入通过。增量复核的新问题说明属于先前遗漏、修复回归还是范围外发现。
