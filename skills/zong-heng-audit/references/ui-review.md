# 页面取证

设计稿和用户可见页面走同一套纵横问法；这里只补依据、浏览器走查和证据边界。

## 依据与边界

- **设计稿**审的是能否作为实现依据。依据是参数文件给出的设计稿与页面依据（缺省：用户裁决、需求与规格、项目的界面规范）。运行证据允许模拟，但身份、状态和业务关系要自洽。结论是“可作实现依据”或“须先改稿”；产品效果由参数文件指定的确认方确认（缺省：用户）。
- **生产页面**审的是真实业务链路是否完整。依据另加已确认的设计稿。运行证据要真实接口、持久化和权限，模拟只证明局部。
- 确认预览运行的版本就是被审版本。现有实现不是设计依据。设计合理而正式规范没覆盖的，归为补规范；改变规范已定义的状态、权限或异常流的，核对有效裁决，没有就按裁决请求格式上报。
- 页面装配（共享组件、路由、离开保护、缓存、关联页面）凡能改变本次可观察结果的，都要审到。组件“调用了退出”不证明用户到了目标页；提示弹出不证明保存或生效。

## 浏览器走查

按受影响的用户旅程**在真实浏览器里实际操作**，不以读源码代替；适用于当前版本的已有浏览器证据可以复用。

- 生产页面保存后，用刷新、重新进入或关联页面回读，确认持久化与生效。
- 从断点一问选实际风险：校验失败、请求失败、取消、重复提交、断网、版本冲突。共享的失败机制复用基座证据，页面只核实际接入与它特有的恢复终点。
- 用参数文件给出的走查账号（缺省：样例数据里的真实账号）。命题涉及权限或可见性时切换对应角色，并核对真实请求：隐藏或禁用不等于服务端校验。
- 按受影响面选看：形态与受众（布局、按钮层级、文案、空态）、深浅色与窄屏（375 宽、长内容、无意外横向溢出）、交互与恢复（取消重入、刷新、键盘与焦点）、数据与可见性（敏感字段、空值、同名数据）。
- 截图存主审指定的任务临时目录（见 `git-workflow` 的“提交”节），实际看过的才引用。起不来写 `NOT_RUN`，状态看不见写 `NOT_SEEN`，附原因；工具或启动失败是取证缺口，不是产品缺陷。

## 问题判断

规范违反、功能错误、与已确认设计不一致可作必须修复的候选；主观优化只作建议。风险写清入口、权限和正常操作能否触发；正常操作触发不了的假设异常，不作为加确认、校验或锁的理由。
