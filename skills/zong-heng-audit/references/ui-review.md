# 设计稿与页面取证

设计稿和用户可见页面走同一纵横方法；本文件补充依据、真实浏览器走查和证据边界。

## 依据与边界

| | 设计稿 | 生产页面 |
|---|---|---|
| 审查命题 | 是否满足需求与规范，能否作为实现依据 | 是否满足需求、规范与已确认设计，真实业务链路是否完整 |
| 依据 | 参数文件给出的设计稿与页面依据（缺省：用户裁决、需求与规格、项目的界面规范） | 同左，加已确认的设计稿 |
| 运行证据 | 允许模拟，但身份、状态和业务关系须自洽；标明刷新是否重置样例 | 真实接口、持久化和权限；模拟只证明局部 |
| 结论边界 | 可作实现依据 / 须先改稿；产品效果由参数文件指定的确认方确认（缺省：用户） | 按已验证范围报告；Ready 与合并交给交付流程 |

确认预览运行的版本就是被审版本。现有实现不是设计依据；已正式承接到其他任务的样例数据缺口列为不证明边界。设计合理但正式规范没覆盖时，归为补正式规范；改变规范已定义的状态、权限或异常流时，核对有效裁决，没有裁决按参数文件的裁决请求格式上报。

页面装配（共享组件、路由、离开保护、缓存、关联页面）凡能改变本次可观察结果的，都并入原覆盖索引。组件确认“调用了退出”不证明用户到了目标页；提示弹出不证明保存或生效。

## 浏览器走查

按受影响用户旅程**在真实浏览器里实际操作**，不能以源码阅读代替；可复用适用于当前版本的已有浏览器证据。

- 生产页面保存后，用刷新、重新进入或关联页面回读确认持久化与生效。同一对象的状态链保持连续；独立场景可各自建立前置状态，各走到自己的可观察终点。
- 从关键失败 / 恢复边选实际风险：校验失败、请求失败、取消、重复提交、断网、版本冲突。共享失败机制复用基座证据，页面只核实际接入与特有恢复终点。
- 用参数文件给出的走查账号（缺省：样例数据里的真实账号）。默认身份走一般流程，命题涉及权限或可见性时切换对应角色，并核对真实请求：隐藏或禁用不等于服务端校验。
- 截图存主审指定的任务临时目录（见 `git-workflow` 的“提交”节），报告列路径，实际看过的才引用。
- 起不来写 `NOT_RUN`，状态看不见写 `NOT_SEEN`，附原因和受影响命题；工具或启动失败是取证缺口，不是产品缺陷。

按受影响面选维度：

| 维度 | 检查 |
|---|---|
| 形态与受众 | 布局、组件、按钮层级、文案、空态，对照设计稿与依据中的界面规范 |
| 深浅色与窄屏 | 深色、375 宽、长内容、折叠与抽屉；无意外横向溢出 |
| 交互与恢复 | 连续主流程、取消重入、刷新、键盘与焦点、命中的失败恢复边 |
| 数据与可见性 | 对应身份的可见与可改范围、敏感字段、空值与同名数据 |

风险写清入口、权限和正常操作能否触发；正常操作触发不了的假设异常，不作为加确认、校验或锁的理由。

## 问题判断

规范违反、功能错误、与已确认设计不一致可作必须修复候选；主观优化只作建议。每项附复现步骤、实际与预期、依据、影响面和最小修复方向。
