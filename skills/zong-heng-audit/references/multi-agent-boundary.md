# 分工与回收

派审查或浏览器取证子代理时使用。模型与档位按参数文件的子代理模型行；缺省沿用当前会话的模型。

## 派发

纵向按完整旅程分，横向按同一单元的出现面分；关联紧密、一个上下文能深入承载的交给同一代理，装不下再拆，并指定谁检查交接处。未委派的覆盖归主审。文件、RR、页面区域和界面视角只用来定位，不作完成依据。

brief 用自然语言写三件事，已有材料给位置：

- **审什么**：要证明的命题、锚点或地图落点、完整起止点或出现面。只委托固定复现步骤时，说明结果只证明这些步骤。
- **据什么判断**：固定版本、原始材料、正式依据与用户裁决，以及可继承的证据。
- **做到哪里**：可观察终点、关键失败 / 恢复路径、所需真实装配，哪些允许模拟。审查分组读 [纵横审查方法](method.md) 的答题规则与本向视角，按 [覆盖索引](output-contracts.md#覆盖索引) 的格式返回各视角的答案、证据、候选问题和未完成部分。

例：委托“草稿重载恢复”走查，要沿真实编辑页走到恢复编辑或实际退出，包括离开保护；只查读取函数返回值不足以承接这个命题。

子代理只向主审返回结果：不面向用户，不联系开发代理或其他线程，不写 GitHub、任务状态或正式文档，不出正式 RR 或总体结论。

## L3 独立分组

两向各至少一个独立分组，共用固定版本、原始证据和工作地图。首轮用干净上下文（支持 `fork_turns` 时用 `none`）；brief 不带开发或主审对话、其他组发现、预期结论和后置探针。定向补审和修复复核可复用原组上下文。

主审收齐首轮结果后才跑后置探针和交叉收敛。必需组失败时按 [输出合同](output-contracts.md) 报告 L3 未完成；主审自己补缺失组只能算另起的完整 L2，不冒充 L3。

## 回收

先按输出合同的验收规则核返回的覆盖索引，再把实际覆盖与派出的命题对照，按 [交叉收敛](method.md#交叉收敛) 核对，重点看分组交接处。脚本证据影响结论时，核对决定性断言的预期与原始观察，不只采信 `PASS / FAIL` 标签。完成了步骤却没到终点时，追问阻断在哪、还缺哪段证据。
